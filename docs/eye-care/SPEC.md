# WorkBreath（息刻）护眼功能规格

- 状态：产品行为已实现，持续验证
- 代码底座：Work Review `5cae4bee67100f58319d32fe1cb31473089800a6`
- 首发平台：Windows

## 1. 目标与边界

本项目继续以 WorkBreath（兼容旧 Work Review 数据）为主体，只移除桌宠功能，并在不削弱其工作记录与复盘能力的前提下增加强制护眼休息。

### 保留

- 前台应用、窗口标题、浏览器与使用时长记录。
- 截图、OCR、SQLite、时间线、统计、小时摘要和日报。
- 导出、工作助手、AI 接入、隐私规则、存储管理、本地 API、Bot、更新与开机启动等非桌宠能力。
- 现有小时摘要和日报的语义与入口；新增的“本轮回顾”不能替代它们。

### 移除

- 桌宠窗口、桌宠视觉素材、桌宠专属设置与托盘开关。
- 桌宠气泡、主动提醒、桌宠待跟进/专注交互、点击穿透和位置跟随。
- 只服务于桌宠的全局输入桥接与平台扩展。
- 旧的桌宠休息提醒；其配置需要迁移到新的护眼设置，而不是直接丢失用户选择。

移除桌宠时不得顺带删除活动分类、窗口监测、输入空闲检测、通知、AI 助手或摘要等共享能力。

### 新增

- 独立于桌宠和活动录制开关的护眼计时器。
- 默认工作 40 分钟、强制休息 3 分钟；两项均可在设置中修改。
- 默认连续无输入 5 分钟视为一次自然休息；该阈值可修改。
- 休息前 30 秒预告，不提供延后或跳过。
- 每块显示器上的强制休息层。
- 固定休息正常结束后默认请求系统锁屏，并允许用户关闭。
- 休息完成并检测到用户回来后的单周期活动摘要。

### 不在本轮扩大范围

- 不删除或重做 Work Review 的其他功能。
- 不引入第二套截图、OCR、数据库或 AI 管线。
- 不复制 EyeLoveU 的代码、素材、品牌或像素级界面。
- 不引入 GPL 或来源/许可证不明的实现代码。
- 不在实现过程中顺便完成商业版、代码签名或发布。

## 2. 用户体验

### 工作阶段

1. 护眼功能启用后累计有效屏幕使用时间。
2. 到期前 30 秒给出轻量预告；预告不阻挡当前工作。
3. 预告不能延后本轮休息，也不出现“跳过”按钮。

### 强制休息阶段

1. 达到工作阈值后，所有已连接显示器同步进入休息状态。
2. 每块显示器由一个全屏透明拦截层覆盖输入；中央显示约占该显示器 75%～80% 的柔和彩色休息卡片，外围仅变暗。
3. 页面只显示简短护眼提示、剩余时间和进度，不显示截图、工作列表、摘要或长文。
4. 普通关闭、`Alt+F4`、`Esc`、最小化、`Win+D`、主窗口或托盘退出都不能跳过正在进行的休息。
5. 显示器热插拔后，新增显示器必须补建休息层；消失的显示器不能拖住整个休息流程。
6. 后端是休息状态的唯一事实来源；单个休息窗口意外消失时由 watchdog 恢复。
7. 倒计时结束后所有休息层自动释放，不要求用户进行屏幕内操作。
8. “休息结束后锁屏”开启时，应用随后请求操作系统锁定当前会话；请求失败或超时也不能继续遮挡用户。
9. 系统任务管理器、锁屏、注销、重启等系统级逃生不拦截；应用锁屏使用系统能力，不把休息层伪装成系统锁屏。

### 故障逃生

- 正常界面不提供跳过。
- 保留一个不在 UI 展示的特殊组合键，需持续按住数秒才能解除当前休息。
- 应急解除应留下本地诊断记录，但不得上传或作为惩罚性统计。
- 任何窗口或前端故障都不能使电脑在休息时长结束后继续被遮挡。

### 休息后回顾

1. 休息倒计时结束后进入等待返回状态，并立即释放遮挡。
2. 若开启“休息结束后锁屏”，系统会先进入锁屏；解锁后的首次有效键鼠输入视为用户返回。
3. 检测到首次有效键鼠输入后，在 WorkBreath 主窗口展示“本轮回顾”。
4. 回顾范围严格限定为本轮工作开始到进入休息之前。
5. 确定性统计必须先可用：总时长、主要应用、网站和已有 OCR 关键词。
6. AI 只能在现有用户配置和隐私边界内做可选概括；生成失败或尚未完成时不能阻塞休息或回顾展示。
7. 周期回顾不得新建高频截图任务，不得自动扩大截图保留范围，也不得自动把本地截图上传云端。

## 3. 计时语义

活动记录时长与护眼疲劳时长可以共享系统信号，但两者是不同业务数据，不能复用 Work Review 当前受截图配置影响的空闲算法。

### 主状态

- `WORKING`：累计本轮有效使用时间。
- `PRE_BREAK`：已进入 30 秒预告，继续累计并等待强制休息。
- `RESTING`：同步显示所有休息层并累计休息时间。
- `WAITING_RETURN`：休息已完成、遮挡已释放，等待用户回来后展示本轮回顾。

### 输入与系统状态

- `ACTIVE`：存在有效键鼠输入，或存在可验证的屏幕使用信号。
- `IDLE_CANDIDATE`：暂无输入但未达到自然休息阈值；不增加疲劳时间，也不清空已累计时间。
- `AWAY`：连续无输入达到自然休息阈值。
- `LOCKED`：系统会话已锁定。
- `SUSPENDED`：系统进入睡眠或挂起。
- `PAUSED`：用户在非休息阶段明确暂停护眼功能；活动录制的暂停不能隐式暂停护眼计时。

### 转换规则

1. 使用单调时钟累计进程存活期间的时间，不能直接用墙上时间做逐 Tick 累加。
2. 短暂无输入、短暂锁屏或短暂睡眠只暂停本轮累计，恢复后保留此前疲劳时间。
3. 普通无输入连续达到自然休息阈值（默认 5 分钟）后，本轮疲劳清零，回来开始新周期。
4. 明确锁屏或睡眠持续达到当前配置的休息时长后，视为已经完成自然休息，回来开始新周期。
5. 锁屏、睡眠和未知时间段不计入有效使用时间。
6. 休息已经开始后，改变设置、暂停录制或关闭主窗口不能缩短当前休息。
7. 重启不能成为绕过手段：需持久化足够的周期状态；异常退出后的未知区间不能被计入使用时间。若上次处于休息阶段，恢复时根据已保存剩余时间和可信的离开时长决定完成或继续，且必须防御系统时间回拨/跳变。
8. 视频、会议、全屏应用默认不豁免强制休息；若平台能提供可靠的“仍在看屏幕”信号，可用于避免把视频观看误判为自然休息，但不能依赖截图开关。

产品文案应表述为“估算的有效屏幕使用时间”，不能承诺识别用户眼睛是否正在看屏幕。静态阅读等无输入场景存在估算误差，用户可通过自然休息阈值调整容忍度。

## 4. 配置与兼容

- 新配置至少包括：护眼启用、工作时长、休息时长、自然休息阈值、预告时长和休息结束锁屏。
- 默认值分别为：启用、40 分钟、3 分钟、5 分钟、30 秒、结束后锁屏开启。
- 时长必须为正数并有合理上限；后端负责最终归一化，不能只依赖前端校验。
- 旧 `break_reminder_enabled` 和 `break_reminder_interval_minutes` 应有确定性迁移；已有合法工作间隔优先保留，缺省或非法值使用 40 分钟。
- 旧桌宠字段在读取旧配置时不得导致启动失败；迁移完成后不再出现在新设置 UI。
- 护眼设置放在普通设置区域，不再依赖“外观/桌宠”页面。
- 护眼计时默认不依赖活动录制、截图、OCR、AI、桌宠或网络状态。

## 5. 隐私与数据

- 休息层和本应用自有窗口不得进入截图、OCR、活动时长或周期回顾。
- 周期回顾只读取现有数据库中当前周期范围内、已通过现有隐私过滤的数据。
- `Ignored` 与 `Anonymized` 规则继续生效；周期回顾不能绕过它们补取标题、URL、截图或 OCR。
- AI 增强沿用现有模型、联网和云端视觉授权，不增加隐式出网。
- 没有数据时显示明确的空状态，不使用模型猜测用户做过什么。

## 6. 调研结论与约束

- [Work Review](https://github.com/wm94i/Work-Review) 是唯一代码底座，提供活动记录、截图/OCR、统计和摘要；其当前桌宠提醒与护眼需求不等价。
- [Entracte](https://github.com/drmowinckels/entracte) 是主要实现参考：同为 Tauri/Rust，已有多显示器 Overlay、80% 居中窗口、调度和 watchdog 思路；其 React 前端、macOS 优先实现、Skip/Postpone 与深色界面不照搬。
- [Stretchly](https://github.com/hovancik/stretchly) 是成熟行为参考：借鉴严格模式、全屏/多屏、自然休息与异常恢复经验；不引入 Electron 技术栈或其双周期模型。
- [BreakTimer](https://github.com/tom-james-watson/breaktimer-app)、[Workrave](https://github.com/rcaelers/workrave) 和 [ActivityWatch](https://github.com/ActivityWatch/activitywatch) 只提供状态机、长期边界案例与活动记录参考，不复制 GPL 代码。
- EyeLoveU 只提供交互参考；没有可依赖的可信 Windows 开源源码或明确许可证。
- 当前开发环境不是 Windows，Windows 会话事件、休眠、DPI、热插拔与 Overlay 强制性必须通过实机验证，不能以 Linux 测试替代。

## 8. 完成标准

只有在以下条件全部满足时，才能声称本轮实现完成：

1. 本规格中的可观察结果均有新鲜测试或实机证据。
2. 现有自动化测试与构建通过；已知的上游基线失败需单独记录，不能伪装为本次通过。
3. Windows 实机至少覆盖锁屏/解锁、睡眠/唤醒、双显示器、不同 DPI、热插拔、关闭绕过、紧急退出和 Overlay 排除。
4. 桌宠已删除，但非桌宠能力没有未经授权的删除或降级。
5. 没有新增隐式截图、隐式上传或超出现有设置的隐私范围。
6. 发布、推送、PR、签名或部署仅在用户明确授权后执行；`v1.4.1` 发布已于 2026-08-10 获得授权。
