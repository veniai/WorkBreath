# 1.6.0 实现与验证记录

核对日期：2026-09-24。本报告记录发布前证据；正式发布状态以 GitHub Release 为准。

用户已确认问题发生在 **Windows 控制端本机**，息刻与 ToDesk 都运行在操作电脑上。此次修复按本机窗口覆盖场景验证，不涉及被控端画面排除。

## 项目与基线

- 开源主线：`veniai/WorkBreath`（息刻），本次升级基线为 `v1.5.11`。
- 本次候选基于 `origin/main@5f0267b`，其代码树与 `v1.5.11` 相同。
- 最初会话目录属于 `veniai/WorkBreath-KylinV10`，是基于 WorkBreath 的麒麟 V10 ARM64 内网适配版，代码版本为 1.5.9。其 X11 独立遮罩、离线 OCR 和 CKAI 更新提醒不能直接替代开源版的 Windows 窗口及签名自动更新实现。
- 本地分支：`fix/v1.6-rest-reliability`。版本号已统一为 1.6.0。用户在获知自动验证结果及实机验证限制后，明确要求正式推送更新。

## 代码排查结论

| 范围 | 结论与本次处理 |
| --- | --- |
| 全屏休息层 | 1.5.11 进入全屏后只调用 show/focus，未恢复最小化状态，也未重新抬升原生窗口层级。Windows Tao 0.34.8 的置顶 setter 在状态标志不变时跳过操作。本次增加显式 Z-order 恢复和最小化恢复。 |
| 多显示器 | 原实现每秒逐屏请求焦点，并忽略显示器数量不变时的几何变化。本次只在休息层均失焦时请求一次焦点，按物理位置/尺寸修复覆盖。 |
| 窗口失败处理 | 原来多数窗口操作失败被忽略，单个窗口创建失败会提前结束整个同步。本次记录操作失败、继续尝试显示和置顶，并继续覆盖其他屏幕。 |
| 加载与事件 | 原休息层加载主入口，且单窗口定向通知与全局广播重复。本次增加独立 HTML/JS 入口，取消重复定向事件。 |
| 倒计时体验 | 原快照和订阅并发，慢快照可能覆盖新事件。本次先订阅并防止旧快照覆盖最新状态；等待状态时显示占位符；支持系统减少动态效果设置；独立入口保留拖放导航和右键菜单保护。 |
| 计时、存储、采集 | 原有护眼状态机独立于录制/截图/OCR，使用单调时钟，并按状态变化或 30 tick 持久化。保留这些已有优化，不调整工作时长或数据语义。 |
| 自动升级 | 开源版已有平台更新包校验、多源回退和签名机制。本次保留更新端点、公钥、应用 identifier 与数据目录，不套用麒麟版的仅提醒机制。 |
| 依赖 | CI 审计发现 h2 / rustls 新公告。直接 HTTP 客户端更新至 reqwest 0.12.28，将 h2 更新至 0.4.19、rustls 更新至 0.23.45；保留 json、SOCKS 和默认 native TLS 配置。修复后仓库 Rust 审计门禁通过，未新增忽略项。npm 运行时 high 门禁通过，保留 DOMPurify moderate 公告记录，未把公告当作已验证的应用漏洞。 |

这些代码缺口与用户报告相符，但尚未在用户的 ToDesk 环境中复现，不能据此宣布唯一根因或实机修复完成。

## 性能证据

相同机器分别构建 1.5.11 和候选，统计休息入口的 JS/CSS 及其静态依赖；旧版包含主入口和动态加载的休息组件，新版只包含独立休息入口。

| 指标 | 1.5.11 | 1.6.0 候选 |
| --- | ---: | ---: |
| 入口依赖资源总字节数（未压缩） | 576,373 | 276,331 |
| 资源减少 | — | 52.1% |

这是构建产物体积比较，不代表已测得的内存、CPU 或启动耗时变化；真实多屏性能仍需在目标机器观测。

依赖修复后，453 项 Rust workspace 测试、Linux 全目标检查和 Windows GNU 全目标交叉检查再次通过。GitHub Windows/macOS CI 和依赖审计均通过。另用本地隔离服务完成 reqwest 0.12 的直连及 SOCKS5 主机名代理 JSON 往返验证，不访问用户账号或外部业务服务。

本地检查不是独立审查或发布验收。复验命令：

```sh
node --test
npm run build
cargo check --workspace --all-targets
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
npm audit --registry=https://registry.npmjs.org --omit=dev --audit-level=high
```

浏览器检查沿用仓库 Playwright。启动本地 Vite 后运行：

```sh
README_CAPTURE_BASE_URL=http://127.0.0.1:4186 \
README_CAPTURE_LOCALES=zh-CN \
README_CAPTURE_OUTPUT_ROOT=/tmp/workbreath-v1.6-ui-smoke \
```

浏览器使用模拟 Tauri IPC，验证显示、倒计时和前端交互；不能证明 Windows 原生 Z-order、远程键盘独占、系统锁屏或真实多屏行为。

## 发布决策与后续实机验证

用户已明确要求沿用仓库正式流程推送 1.6.0。使用已通过的原生 CI、依赖审计及签名验证证据准备发布，不把尚未执行的 ToDesk 实测或独立审查记录成通过。仓库没有强制审批规则；HAPI 托管审查适配器不可用，未伪造审批或绕过保护规则。

后续仍需在 Windows 控制端本机记录系统/ToDesk 版本及显示器配置，验证窗口/全屏模式、多屏混合 DPI、最小化恢复、紧急退出和结束释放。1.5.11 实际安装升级后的设置与历史数据保留也尚待实测。具体矩阵见 `WINDOWS-VALIDATION.md`。

正式发布使用仓库标签工作流生成各平台安装包、签名与三个 updater 清单；发布后检查版本、平台条目、下载地址及签名。只有正式清单可用后，1.5.11 的“检查更新”才能获取 1.6.0。
